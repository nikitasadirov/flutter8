# SRS 9 — отчёт (Post Explorer)

## Что сделано
1. **Launcher Icon** — `assets/icon/app_icon.png`, пакет `flutter_launcher_icons` (dev-зависимость) и секция `flutter_launcher_icons` в конце `pubspec.yaml`. Генерация: `dart run flutter_launcher_icons`.
2. **Unit Test** — `test/post_logic_test.dart` (16 тестов: AppException, PostCache, PostRepository) + уже существовавший `test/post_repository_test.dart` (6 тестов).
3. **Widget Test** — `test/posts_widget_test.dart` (8 тестов): главный экран, поиск/сброс, сортировка, ошибка + повтор, переход на экран деталей и назад, форма создания поста (пустой ввод, корректный ввод).
4. **Доп. задание (одно, самое лёгкое)** — тестирование некорректных входных данных: пустая форма, строка из пробелов, слишком короткий текст; проверка, что `createPost` при этом не вызывается.

## Запуск
```
flutter pub get
dart run flutter_launcher_icons
flutter test
```

## Ответы на контрольные вопросы
1. **Launcher Icon** — иконка приложения на главном экране и в списке приложений.
2. **flutter_launcher_icons** — автоматически генерирует иконки всех нужных размеров для Android и iOS из одного PNG.
3. Настраивается в `pubspec.yaml`, секция `flutter_launcher_icons`.
4. **Unit Test** — проверка отдельной функции/метода/класса без UI.
5. Unit Test проверяет логику и результаты вычислений; Widget Test — отображение и взаимодействие с виджетами (кнопки, текст, поля).
6. `expect()` сравнивает фактический результат с ожидаемым (matcher); при несовпадении тест падает.
7. `test()` объявляет один unit-тест: название и функцию с проверками.
8. `testWidgets()` объявляет widget-тест; даёт `WidgetTester` для построения виджетов, нажатий, ввода текста и `pump()`.
9. `flutter test` запускает все тесты из папки `test/` и показывает результат.
10. Чтобы найти ошибки до пользователей, не ломать старый функционал при изменениях и снизить стоимость исправлений.
